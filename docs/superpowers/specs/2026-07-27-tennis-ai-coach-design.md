# AI Tennis Coach — дизайн MVP

Дата: 2026-07-27  
Статус: одобрен для реализации

## Идея

Личный мобильный PWA-инструмент AI-тренера по теннису. Он помогает подготовиться к матчу, получить одну короткую корректировку на переходе и перестроить план между сетами. Все вводы и советы сохраняются в истории матча.

## Сценарии

### 1. Подготовка к матчу

Ввод:

- показатели последней доступной записи `Oura-v2.health_logs`: readiness, sleep score, average HRV и дата данных;
- энергия, последний приём пищи, физическое состояние и настрой;
- тип матча, соперник, покрытие, погода и формат сессии.

Oura необязательна. Если запись отсутствует или устарела, приложение показывает это и позволяет продолжить без неё.

Выход: короткий связный бриф — тактика, физическая дозировка и ментальный фокус. При упоминании боли совет не должен подталкивать играть через опасные симптомы.

### 2. Переход между геймами

Быстрый ввод по фиксированным темам: форхенд, бэкхэнд, подача, приём, движение, игра у сетки. Для каждой темы — «идёт», «не идёт» или «пропустить». Затем состояние, текущий счёт и подающий.

Выход: одна конкретная мысль на следующий гейм.

### 3. Новый сет

Тот же ввод плюс оценка запаса сил. Выход: 2–4 коротких предложения с тактикой и установкой на следующий сет.

## Контекст AI

Совет во время матча получает:

- контекст матча и подготовительный бриф;
- снимок Oura, если он использовался;
- текущий счёт и подающего;
- текущие наблюдения;
- предыдущие события и советы этого матча.

Модель задаётся через `OPENAI_MODEL`. Ответ ограничивается по длине и очищается от пустого результата.

## Архитектура

```text
PWA (GitHub Pages)
        ↓ HTTPS + личный API key
Flask backend (Render)
        ↓
Supabase
  ├─ существующие users + health_logs из Oura-v2 (только чтение)
  └─ matches + match_prep + match_events
        ↓
OpenAI API
```

Отдельных запросов к Oura API в tennis-coach нет. Пользователь Oura задаётся через `OURA_USER_ID`. В `match_prep` сохраняется снимок показателей и дата источника, поэтому история матча не меняется при обновлении `health_logs`.

## Жизненный цикл матча

- Одновременно допускается один матч в статусе `preparing` или `in_progress`.
- Активный матч восстанавливается с backend после перезагрузки или повторного открытия PWA.
- Счёт хранится структурированно (`sets`, `game`, `serving`) и отображается одной компактной строкой.
- Повторная отправка одного события защищена idempotency key.
- Завершённый матч получает итоговый счёт; ошибочно начатый можно отменить.

## Экраны

1. **Подготовка:** свежесть Oura, контекст, самочувствие, бриф, начало матча.
2. **Матч:** счёт всегда сверху, быстрые карточки, совет, завершение/отмена.
3. **История:** список матчей и полный таймлайн.
4. **Настройки:** адрес backend и личный API key на устройстве.

## Надёжность

- Понятные состояния загрузки и ошибки сети.
- Повтор запроса не создаёт дубль события.
- Ошибка OpenAI не создаёт новый матч.
- Все входные данные валидируются на backend.
- История остаётся доступной после закрытия вкладки при наличии сети.

## Не входит в MVP

- multi-user и регистрация;
- полноценный офлайн-режим;
- голосовой ввод/вывод;
- автоматический теннисный скоринг по каждому очку;
- статистически значимый экран «Паттерны».

Данные для будущих паттернов сохраняются структурированно. Экран имеет смысл добавлять после накопления хотя бы 8–10 матчей.
